技能管理功能 - 审查意见

方案整体思路清晰，UI 设计合理。发现 4 个问题 和 5 个优化点。

🔴 问题 1（必须修复）：写 companies.mjs 有语法风险

问题：companies.mjs 是 ES Module JavaScript 文件，不是纯 JSON。 直接用字符串操作插入新技能（如在 skills: [...] 数组里追加一项）， 容易出现语法错误（缺逗号、引号不匹配、尾部逗号等），导致整个模块加载失败。

场景示例：

// companies.mjs 当前（合法）
skills: ["Agent", "AIGC", "C++"]

// 简单字符串追加后（可能出错）
skills: ["Agent", "AIGC", "C++"JAX"]  // ➔ 缺逗号
skills: ["Agent", "AIGC", "C++", JAX]  // ➔ 缺引号
skills: ["Agent", "AIGC", "C++", "JAX",]  // ➔ 尾部逗号（ES Module 合法但 JSON 不合法）

修复：分两种策略

// 策略 A（推荐）：只写 companies.json，companies.mjs 改为从 JSON 读取
// companies.mjs 改为：
import companiesData from './companies.json' assert { type: 'json' };
export default companiesData;
// 这样只需维护一个数据源（companies.json），mjs 自动同步

// 策略 B（备选）：用 AST 或正则精确操作
// 用 Node.js 的正则替换，确保语法正确
function addSkillToMjs(companyKey, newSkill) {
  const content = fs.readFileSync('companies.mjs', 'utf-8');
  // 匹配 skills: [...] 数组
  const regex = new RegExp(
    `(${companyKey}[\s\S]*?skills:\s*\[)([\s\S]*?)(\])`
  );
  const match = content.match(regex);
  if (!match) return false;
  // 解析已有技能
  const skills = JSON.parse('[' + match[2] + ']');
  skills.push(newSkill);
  skills.sort();
  // 替换回文件
  const newContent = content.replace(regex,
    '$1' + skills.map(s => '"' + s + '"').join(', ') + '$3'
  );
  fs.writeFileSync('companies.mjs', newContent);
  return true;
}
推荐策略 A：让 companies.mjs 变成 companies.json 的薄包装层， 所有写入操作只修改 companies.json，从根本上避免语法错误。 这也是之前代码审查中发现的"文档与代码不一致"问题的根治方案。

🔴 问题 2（必须修复）：缺少输入校验

问题：用户可以输入空字符串、纯空格、已存在的技能、超长字符串、特殊字符等， 这些都会写入配置文件，污染数据。

修复：后端校验

// server.js POST /api/skills
app.post('/api/skills', (req, res) => {
  const skill = (req.body.skill || '').trim();
  
  // 校验
  if (!skill) return res.status(400).json({ error: '技能名称不能为空' });
  if (skill.length > 30) return res.status(400).json({ error: '技能名称不超过 30 字符' });
  if (/[;{}\[\]()]/.test(skill)) return res.status(400).json({ error: '包含非法字符' });
  
  // 检查重复
  const allSkills = getAllSkills();
  if (allSkills.includes(skill)) {
    return res.status(409).json({ error: '该技能已存在' });
  }
  
  // ... 写入逻辑
});

🔴 问题 3（必须修复）：新增技能后没有触发重新合并

问题：新增技能写入 companies.json 后， 前端 jobsData.json 不会自动更新。 新技能在矩阵中会显示为全灰（所有岗位都没有该技能），直到下次手动刷新爬虫才会重新提取。

两种处理方式：

方式 效果 适用场景
方式 A：不重新合并 新技能显示为全灰，下次刷新才生效 只添加未来会用到的技能（低频）
方式 B：重新提取技能 立即重新跑一遍 extractSkills()，填充已有岗位的技能匹配 添加遗漏的技能，需要立即补全矩阵

建议采用方式 A（不重新合并），但前端要明确告知用户：

// 添加成功后的提示
toast('技能 "JAX" 已添加。下次刷新数据后，矩阵会自动匹配该技能。');

🔴 问题 4（必须修复）：同步写两个文件无原子性

问题：如果写了 companies.json 后、写 companies.mjs 前服务崩溃， 两个文件内容不一致，导致下次启动数据错乱。

修复：先写临时文件，再原子重命名

import { renameSync, writeFileSync } from 'fs';

function safeWriteFile(filePath, content) {
  const tmpPath = filePath + '.tmp';
  writeFileSync(tmpPath, content);
  renameSync(tmpPath, filePath);  // 原子操作
}

如果采用策略 A（只写 JSON），这个问题自然消失，因为只改一个文件。

🟡 优化点 5：大小写和空格处理

用户可能输入 "python"（小写）或 " Python "（带空格），导致重复技能。

建议：后端自动规范化：

function normalizeSkillName(skill) {
  return skill.trim()
    .replace(/\s+/g, ' ')     // 多个空格变一个
    .replace(/-(.)/g, (_, c) => c.toUpperCase())  // kebab-case → CamelCase
    // 不强制大写首字母，保持用户输入风格
    // 但重复检查时忽略大小写
};

// 重复检查忽略大小写
const exists = allSkills.some(s => s.toLowerCase() === skill.toLowerCase());
if (exists) {
  return res.status(409).json({
    error: '该技能已存在',
    existingName: allSkills.find(s => s.toLowerCase() === skill.toLowerCase())
  });
}

优先级 问题 修复方案
必须 写 companies.mjs 有语法风险 策略 A：mjs 改为从 JSON 读取的薄包装层
必须 缺少输入校验 后端校验空/长/特殊字符/重复
必须 新增后没有触发重新合并 不自动合并，提示用户下次刷新生效
必须 同步写两个文件无原子性 临时文件 + 原子重命名 / 或只写一个文件
建议 支持删除技能 DELETE /api/skills + 确认弹窗
建议 技能分类显示 按 10 大类分组，可折叠
建议 技能重命名 双击编辑 + 同步更新 jobsData
建议 技能使用统计 标签显示匹配数量，0 次灰色
建议 大小写和空格处理 trim + 忽略大小写查重
结论：方案 UI 设计合理，但有 4 个必须修复的问题。 最关键的是问题 1（companies.mjs 语法风险），建议优先解决——让 mjs 变成 JSON 的薄包装层， 从根本上消除双文件同步问题。这是一个架构级优化，同时也解决了之前"文档与代码不一致"的历史遗留问题。
