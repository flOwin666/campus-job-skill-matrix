刷新暂停/停止方案 - 审查意见

方案设计整体清晰，暂停/停止的数据流完整。但发现 2 个必改问题 和 3 个优化点。

必改问题 1 并发刷新冲突（Bug）

问题：/api/refresh 开始时直接重置 refreshControl = { paused: false, stopped: false }， 如果上一次刷新还在跑，会被覆盖，导致第一次刷新的控制器失效。

修复：加 refreshing 标志位

// server.js
let refreshing = false;  // 新增

app.get('/api/refresh', (req, res) => {
  if (refreshing) {
    return res.status(409).json({ error: '已有刷新任务在运行' });
  }
  refreshing = true;
  refreshControl = { paused: false, stopped: false };
  
  scrapeAll({ controller: refreshControl, onLog: ... })
    .finally(() => { refreshing = false; });  // 结束复位
});
修复效果：防止并发刷新冲突，409 状态码告知前端"已有任务在运行"。

必改问题 2 停止后合并时序不明确

问题：方案写"停止 → 跳出循环，返回已爬数据 ↓ mergeJobs() 合并"， 但没明确 mergeJobs() 是在 scrapeAll 内部调用，还是 server.js 在收到结果后调用。

修复：明确时序，无论全部完成还是被停止都合并

// server.js /api/refresh 回调
scrapeAll({ controller: refreshControl, onLog: ... })
  .then(async (result) => {
    // 无论全部完成还是被停止，都合并已爬数据
    await mergeJobs();  // 合并 _work/ 到 v6/src/jobsData.json
    sendSSE({ 
      type: refreshControl.stopped ? 'partial_done' : 'done', 
      count: result.count 
    });
  })
  .finally(() => { refreshing = false; });

关键点：scrapeAll 被停止时要 resolve 而非 reject，返回 { count: 已爬数量, partial: true }。

修复效果：无论正常完成还是手动停止，已爬数据都会被合并，前端始终显示最新数据。

优化点 1 百度爬虫也要检查暂停

问题：方案写"4 个 Playwright 爬虫"，但百度是 HTTP 爬虫，没有 batch 循环，需要单独处理。

建议：在 baidu.mjs 的 list() 里，每个 seed 处理后检查

// baidu.mjs list()
for (const seed of this.seeds) {
  if (this.controller?.stopped) break;  // ← 加这行
  if (this.controller?.paused) {
    while (this.controller.paused && !this.controller.stopped) {
      await new Promise(r => setTimeout(r, 500));
    }
  }
  // ... 原有逻辑
}

优化点 2 SSE 事件类型区分「部分完成」和「全部完成」

问题：前端需要知道刷新是被停止（部分数据）还是正常完成（全部数据），以显示不同提示。

建议：加 partial_done 事件类型

// server.js 发 SSE
if (refreshControl.stopped) {
  sendSSE({ type: 'partial_done', count: result.count });
} else {
  sendSSE({ type: 'done', count: result.count });
}

// App.vue SSE 监听
if (msg.type === 'partial_done') {
  showToast(`刷新已终止，已保存 ${msg.count} 个岗位`);
}

优化点 3 (可选) UUID 会话标识

问题：当前用内存变量 refreshControl，前端断开重连后状态丢失（方案已标注"后续可加"）。

如果要做，方案是：

  • /api/refresh 返回 { sessionId: 'uuid-xxx' }
  • 前端调 /api/refresh/pause?sessionId=uuid-xxx
  • server.js 用 Map<sessionId, controller> 存储

当前阶段可以不做，留后续优化。
