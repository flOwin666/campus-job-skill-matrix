3. 用户爬取的数据能否永久保存？

关键问题：用户通过聊天触发的爬取结果，是只存在本地内存里，还是会写进数据库让所有访客都能看到？

当前状态 增强方案
爬虫结果写入 本地文件（server.js 运行时） 同上
本地 dev 模式可见 能（直接读本地文件） 能
生产（GitHub Pages）可见 不能（需要手动 push） 爬完后自动 git push
mergeJobs 同步 能（爬完后自动 merge） 能
需要额外操作 管理员手动 git push 全自动

增强方案：爬取完成后自动同步到 GitHub

现有 server.js 里的 refresh 端点已经有 syncJobsToPublic() 和 git push 逻辑。只需要在 trigger_crawl 完成后也走一遍同样的流程：

爬取完成 → mergeJobs() → syncJobsToPublic() → git push → 生产网页自动更新

这样用户通过聊天触发的爬取，完成后所有人都能在 GitHub Pages 上看到新岗位。

但这要求运行 server.js 的机器有 git push 权限，且 LLM_KEY 和 Git 都已配置。如果 push 失败（比如网络问题），数据仍然保存在本地，下次管理员手动 push 即可。
